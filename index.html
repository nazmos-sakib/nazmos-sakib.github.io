An Android app for jogging a five-axis robot arm using touch controls or body gestures. Built with Kotlin and Jetpack Compose, it connects over BLE to an ESP32-S3-ETH bridge, which exchanges commands and status with a B&R X20 PLC over Modbus TCP.

What I learned

  • Connecting Android, an ESP32 microcontroller, and a PLC into a complete robot-control system, with live status flowing back to the app.
  • Working with BLE GATT notifications and buffering newline-delimited commands across fragmented Bluetooth packets.
  • Bridging BLE commands to Modbus TCP registers over Ethernet and coordinating power, homing, and jogging with a PLC state machine in B&R Structured Text.
  • Using CameraX, ONNX Runtime, and a YOLO pose model to turn body keypoints into axis selection and directional jog commands.
  • Handling stop-on-release, communication timeouts, heartbeat watchdogs, and readiness checks across the app, firmware, and PLC.

Architecture

  • Android Bluetooth APIs handle device discovery and connections; Coroutines and StateFlow coordinate asynchronous data and UI updates.
  • ESP32 firmware reads two analog inputs and sends comma-separated values over Bluetooth serial; Room persists readings on the phone.

What I learned

  • Connecting pressure-sensing hardware to an Android app through an ESP32 and Classic Bluetooth.

  • Keeping the Compose interface responsive while receiving sensor readings asynchronously.
  • Separating presentation, domain, and data responsibilities with MVVM, repositories, and dependency injection.
  • Storing sensor data locally with Room and working with analog readings in ESP32 firmware.

PERFORMANCE EVALUATION OF ON-DEVICE AI FRAMEWORKS FOR REAL-TIME GESTURE RECOGNITION: A CASE STUDY IN MOBILE ROBOT CONTROL

Hochschule Schmalkalden
2026
Description

Thesis focuses on comparing different AI frameworks for real-time gesture recognition on Android devices. I developed an Android application that recognizes human body gestures using AI/Yolo26 and uses them to control a robot via Bluetooth. The study compares TensorFlow Lite, ONNX Runtime, PyTorch Mobile, and NCNN, focusing on processing speed, CPU and memory usage, and overall response time to determine which framework performs best on mobile devices.
